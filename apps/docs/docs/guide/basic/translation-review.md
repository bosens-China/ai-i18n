---
title: 翻译校对
description: 在开发环境中查找、修改并固定译文
---

ai-i18n 在 Vite Dev 中提供翻译校对页面。你可以比较原文、自动译文与人工译文，并直接修正不合适的
措辞。保存后，业务页面会通过 HMR 使用新的译文。

## 打开校对页面

1. 运行 `vite dev`。
2. 在业务应用中打开需要校对的页面。
3. 找到终端中的 `ai-i18n Review` 链接并在浏览器中打开。
4. 选择目标语言，开始检查译文。

开发服务器只处理浏览器已经访问过的模块。如果某条文案没有出现，请先打开包含该文案的业务页面，
再刷新校对页面。

## 查看和筛选文案

每条文案分为两部分。左侧显示原文、静态 `comment` 和出现文件；右侧显示自动译文、人工译文与
作用范围。

页面提供以下筛选方式：

- 搜索原文、`comment` 或文件路径；
- 切换需要检查的目标语言；
- 查看全部、待确认或已确认的文案。

页面会在当前浏览器会话中按文案、目标语言和作用范围保留未保存输入。切换筛选、搜索、语言或作用
范围后再返回，仍可继续原来的编辑。刷新或关闭校对页面前，仍应保存需要保留的修改。

静态 `comment` 用于区分文字相同但含义不同的文案。例如，按钮中的“保存”和状态中的“保存”可以
分别设置语境：

```ts
t('保存', { comment: '保存文件按钮' });
t('保存', { comment: '保存状态' });
```

## 选择生效范围

确认或保存人工译文前，需要选择作用范围：

- **当前应用的所有位置**：对 `source` 和 `comment` 相同的文案生效；
- **指定文件**：只对选中的源码文件生效。

同一句原文在整个应用中含义一致时，选择全局范围。只有某个文件需要采用不同译法时，才选择文件
范围。文件范围使用相对于 Vite `root` 的精确路径，不支持目录、路径片段或 glob。

## 确认、修改和继续下一条

“人工译文”会先显示当前作用范围的人工值；没有人工值时显示自动译文或原文回退。主按钮根据当前
状态说明将要发生的操作：

- **确认译文**：内容未改动，但还没有人工译文；保存后把当前内容标记为已确认；
- **保存修改**：输入与当前值不同；
- **已保存**：当前人工译文没有变化，不会重复提交。

主按钮右侧的“继续 →”会在保存成功后聚焦下一条可见文案。编辑时也可以按
<kbd>Command</kbd>/<kbd>Ctrl</kbd> + <kbd>Enter</kbd> 执行相同操作。保存结果会写入
`i18n/overrides.json`，并通过 HMR 更新业务页面。

需要恢复自动译文时，选择原来的作用范围，再选择“撤销人工译文”。这项操作只删除当前语言、
当前文案和当前范围对应的人工译文，不会删除 Translation Memory 中的自动译文。

人工译文必须保留原文中的模板 token。例如，原文包含 `{name}` 时，译文也必须包含 `{name}`。
页面会拒绝保存缺少 token 的译文。

## 与自动翻译的关系

翻译校对不会修改自动译文。自动译文仍保存在 JSON 或 SQLite Translation Memory 中，人工译文则
保存在 `overrides.json` 中。运行时按以下顺序选择最终文案：

1. 匹配文件和 `comment` 的人工译文；
2. 匹配 `comment` 的全局人工译文；
3. 匹配文件的人工译文；
4. 全局人工译文；
5. 自动译文；
6. 原文。

少量关键措辞适合使用校对页面。批量补译与自动化操作更适合使用
[AI 翻译](/guide/advanced/ai-translation)或 [Agent + MCP](/guide/advanced/ai-tools)。

## 使用边界

校对页面默认开启，只注册在 Vite Dev Server 中。它不会进入 Build、Preview 或生产产物。页面只
接受当前 Vite 页面发起的同源 JSON 请求，不提供账号、token 或远程协作能力。

界面资源已经随 `@ai-i18n/vite` 提供。业务项目不需要采用 Vue，也不需要安装额外的 UI 组件库。
如果项目不需要校对页面，可以关闭它：

```ts
aiI18n({
  sourceLang: 'zh-CN',
  locales,
  review: false,
});
```

完整补译流程、人工译文格式和提交规则见[补齐和确认译文](/guide/basic/translations)。
