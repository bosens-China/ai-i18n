---
title: 翻译校对
description: 在开发环境中查找、修改并固定译文
---

ai-i18n 在 Vite Dev 业务页面内提供翻译校对插件。你可以比较原文、自动译文与人工译文，并直接修正
不合适的措辞。保存后，业务页面会通过 HMR 使用新的译文。

先在 Vite 配置中显式注册 Review 插件：

```ts
import { aiI18n } from '@ai-i18n/vite';
import { aiI18nReview } from '@ai-i18n/vite/review';

export default defineConfig({
  plugins: [aiI18n({ sourceLang: 'zh-CN', locales }), aiI18nReview()],
});
```

`aiI18n()` 本身不会开启 Review。不注册 `aiI18nReview()` 时，Dev 页面没有校对入口，服务端也不会
挂载 Review API 或工作台资源。

## 打开页面内校对

1. 运行 `vite dev`。
2. 打开需要检查的业务页面。
3. 点击页面右下角的翻译校对图标，选择目标语言并开始检查。

工作台作为连续区域直接贴在业务页面底边，让你在校对时继续看到页面上下文。标题栏与主 Tab 使用实体
背景，不会透出后面的业务页面。拖动面板上边缘可以向上或向下调整高度；高度只保存在当前浏览器中，
刷新业务页面后会恢复，不会写入项目配置或翻译文件。工作台不提供右侧停靠或全屏模式。

工作台打开后默认显示当前业务 DOM 中实际出现的文案，也可在顶部切换到 **全部页面**。它会匹配当前原文、自动译文和人工译文；带运行时
插值的文案也会按模板占位符匹配渲染结果。SPA 路由或页面 DOM 变化后，列表会自动更新，不会因为某个
模块曾经加载过就把上一页面的文案继续算入当前页面。

工作台首次打开时会加载已有的提取快照，通常来自最近一次 `vite build`。这个过程不会重新扫描源码或
触发自动翻译。随后 Dev 中实际访问的模块会以最新结果更新对应文案；工作台保持可见时会自动获取最新
快照，不需要手动刷新，也不会覆盖未保存输入。工作台不提供独立审查页面。

如果项目还没有任何提取快照，开发服务器只会处理浏览器已经访问过的模块。此时请先在业务应用中
打开包含目标文案的页面，文案随后会自动出现在校对页中。

## 从页面取词

在嵌入工作台顶部选择“页面取词”，面板会暂时收起。移动到目标元素时会出现带角点的定位框；
点击后，工作台会在页面底部重新打开并定位对应消息。定位框会短暂保留，让你确认刚才选中了页面中的
哪个区域，随后自动消失。

静态 HTML 提取可以把精确 occurrence 与 DOM 节点关联，因此点选后会直接选择对应的文件、行和列。
Vue、React 和普通运行时文案不会向业务 DOM 注入可见标记；如果相同渲染值对应多个 `comment`、文件
或调用位置，左侧会从文案列表进入“定位结果”层级，按文件、文案与行列列出所有候选。选择准确的
occurrence 后才会进入对应文案并启用当前位置修订；返回后仍保留原来的当前页浏览范围。它不会默认
把第一项当成点选位置。

按 <kbd>Escape</kbd> 可以退出取词。页面取词只拦截这一次选择点击，不会长期劫持业务事件。

## 查看和筛选文案

校对插件是左右分栏的工作台：左侧用高密度列表显示原文、当前译文预览、确认状态和源码位置；右侧使用
带 Header、背景和边框的独立校对区，只显示自动译文、人工译文与作用范围。工作台使用紧凑间距，并根据
底部面板的可用宽度调整布局。

顶部主 Tab 为 **当前页面**、**全部页面** 与 **设置**（默认 **当前页面**）：

- **当前页面**：只展示当前业务 DOM 中出现的全部文案，不含搜索与状态筛选。
- **全部页面**：可搜索原文、译文、语境或文件，也可按确认状态和文件类型筛选；文件类型来自当前提取结果中实际存在的扩展名，例如 `.html`、`.ts`。宽屏时左侧为筛选栏、中间为列表、右侧为编辑区，窄屏时自动折叠为上下或两栏布局以节省高度。
- **设置**：在深色、浅色和跟随系统之间切换外观；偏好保存在当前浏览器中，不会写入项目配置。

配置多个目标语言时，点击窄版语言轨道中的语言代码即可切换。**全部页面**的语言轨道位于筛选区最左侧，
排在搜索框和确认状态之前；**当前页面**没有筛选区，因此语言轨道位于文案列表最左侧。只有一个目标语言时，
工作台直接使用该语言，不再显示没有选择意义的轨道。

在工作台顶部的 **设置** Tab 中切换外观后，外层入口壳与内层工作台会同步应用主题。

页面会在当前浏览器会话中按文案、目标语言和作用范围保留未保存输入。切换筛选、搜索、语言或作用
范围后再返回，仍可继续原来的编辑。刷新或关闭校对页面前，仍应保存需要保留的修改。

点击文案列表中属于当前页面的文案时，业务页面会平滑滚动到第一个可见的匹配元素，并短暂显示定位框。
这在“当前页面”和“全部页面”中都有效；不在当前 DOM 中的文案只会切换工作台选中项，不会滚动业务页面。
同一文案在页面中出现多次时，列表只负责快速定位第一个匹配元素；需要区分具体源码位置时，仍使用页面取词。

静态 `comment` 用于区分文字相同但含义不同的文案。例如，按钮中的“保存”和状态中的“保存”可以
分别设置语境：

```ts
t('保存', { comment: '保存文件按钮' });
t('保存', { comment: '保存状态' });
```

每条文案会在状态和译文预览下显示一行源码定位。左侧用强调标签展示第一个可用的相对路径、行号和列号，
右侧显示 VS Code 图标。点击图标可以直接跳到该位置，并且不会切换当前选中的文案。同一文案包含多个调用位置时，
普通列表用于快速定位页面元素；通过页面取词进入定位结果后，仍需按文件、行和列选择准确 occurrence。

## 选择生效范围

在人工译文输入框上方，通过左右排列的作用范围 Tabs 选择生效范围：

- **当前位置**：只对当前选中的文件、行和列生效；
- **当前文件**：只对当前选中位置所在的来源文件生效；
- **所有文件**：对 `source` 和 `comment` 相同的全部文案生效。

同一句原文在整个应用中含义一致时，选择所有文件；只有一个文件需要不同译法时选择当前文件；同一
文件内只有某次调用需要不同译法时选择当前位置。文件范围使用相对于 Vite `root` 的精确路径，不支持
目录、路径片段或 glob。位置由 1-based 行号与 0-based 列号持久化；源码移动后旧位置不会自动套用到
相似文案，需要重新选择新位置并清理旧规则。

## 确认、修改和继续下一条

没有当前作用范围的人工译文时，输入框会保持空白；自动译文只在上方展示，可按需选择“使用自动
译文”填入。只有输入非空且 Token 校验通过时，确认按钮才可用。主按钮根据当前状态说明将要发生的
操作：

- **确认译文**：输入新的人工译文后保存为人工覆盖；
- **保存修改**：输入与当前值不同；
- **已保存**：当前人工译文没有变化，不会重复提交。

主按钮右侧的“继续 →”会在保存成功后切换到下一条可见文案。保存结果会写入
`i18n/overrides.json`，并通过 HMR 更新业务页面。

校对页支持以下快捷键：

- <kbd>Command</kbd>/<kbd>Ctrl</kbd> + <kbd>Enter</kbd>：保存当前人工译文；
- <kbd>Command</kbd>/<kbd>Ctrl</kbd> + <kbd>Shift</kbd> + <kbd>Enter</kbd>：保存并继续下一条；
- <kbd>Alt</kbd> + <kbd>A</kbd>：填入当前自动译文；
- 焦点不在搜索框或人工译文输入框时，按上下方向键切换文案。长列表会自动滚动，保持选中项可见。

需要恢复自动译文时，选择原来的作用范围，再选择“撤销人工译文”。这项操作只删除当前语言、
当前文案和当前范围对应的人工译文，不会删除 Translation Memory 中的自动译文。

人工译文必须保留原文中的模板 token。例如，原文包含 `{name}` 时，译文也必须包含 `{name}`。
页面会拒绝保存缺少 token 的译文。

## 与自动翻译的关系

翻译校对不会修改自动译文。自动译文仍保存在 JSON 或 SQLite Translation Memory 中，人工译文则
保存在 `overrides.json` 中。运行时按以下顺序选择最终文案：

1. 匹配出现位置和 `comment` 的人工译文；
2. 匹配出现位置的默认人工译文；
3. 匹配文件和 `comment` 的人工译文；
4. 匹配文件的默认人工译文；
5. 匹配 `comment` 的全局人工译文；
6. 全局人工译文；
7. 自动译文；
8. 原文。

少量关键措辞适合使用校对页面。批量补译与自动化操作更适合使用
[AI 翻译](/guide/advanced/ai-translation)或 [Agent + MCP](/guide/advanced/ai-tools)。

## 使用边界

页面内入口只在显式注册 `aiI18nReview()` 后开启，并且只注册在 Vite Dev Server 中。它不会进入 Build、Preview 或生产产物。页面只
接受当前 Vite 页面发起的同源 JSON 请求，不提供账号、token 或远程协作能力。

界面资源已经随 `@ai-i18n/vite` 提供。宿主是 Web Component，工作台和 UnoCSS 样式加载在 Shadow
DOM 内，不会重置或覆盖业务页面样式。业务项目不需要采用 Vue，也不需要安装额外的 UI 组件库。
完整工作台在第一次打开时才加载；不需要 Dev 校对时，从 Vite `plugins` 中移除 `aiI18nReview()`。

完整补译流程、人工译文格式和提交规则见[补齐和确认译文](/guide/basic/translations)。
