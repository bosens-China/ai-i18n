本页面向需要自定义 ESLint 行为的项目。常规接入请先阅读 [ESLint](/guide/quality/eslint)。

## 手动启用规则

只有需要覆盖预设默认值时，才手动注册规则：

```js
import aiI18n from '@ai-i18n/eslint-plugin';
import { defineConfig } from 'eslint/config';

export default defineConfig([
  {
    languageOptions: {
      globals: { defineI18nMessages: 'readonly' },
    },
    plugins: { 'ai-i18n': aiI18n },
    rules: {
      'ai-i18n/t-static-args': 'error',
      'ai-i18n/no-eager-translation': 'warn',
      'ai-i18n/no-unsubscribed-runtime-state': 'warn',
      'ai-i18n/no-unsubscribed-t': 'warn',
      'ai-i18n/static-candidate-limit': 'warn',
    },
  },
]);
```

| 规则                            | 解决的问题                                |
| ------------------------------- | ----------------------------------------- |
| `t-static-args`                 | 拒绝构建时无法确定或不推荐的 `t()` 参数。 |
| `no-eager-translation`          | 避免过早计算并长期保存译后字符串。        |
| `no-unsubscribed-runtime-state` | 避免缓存或渲染非响应式语言状态快照。      |
| `no-unsubscribed-t`             | 提醒 Vue、React 组件使用订阅版 `t`。      |
| `static-candidate-limit`        | 文案候选数量过大时发出警告。              |
| `no-redundant-auto-import`      | 可选地删除自动导入已提供的显式导入。      |

## 自动导入选项

手动配置自动导入项目时，使用数组准确列出当前框架注入的 API：

```js
'ai-i18n/t-static-args': [
  'error',
  { autoImport: ['t', 'tRef', 'useI18n'] }, // Vue
],
```

翻译静态分析规则只需要列出 `t`、`tRef` 和 `useI18n`。框架自动导入的完整集合见
[自动导入](/guide/basic/auto-import)；新项目优先使用对应的预设。

`no-unsubscribed-runtime-state` 的自动导入选项只列出状态快照 API：

```js
'ai-i18n/no-unsubscribed-runtime-state': [
  'warn',
  { autoImport: ['getLang', 'getLangLoadState'] },
],
```

它会提示模块顶层以及 Vue template / JSX 渲染路径中的直接快照读取。事件处理器、普通函数和
即时日志允许按需读取；规则不追踪跨文件 store 数据流。

`no-redundant-auto-import` 默认不包含在预设中。希望统一为自动导入风格时：

```js
'ai-i18n/no-redundant-auto-import': [
  'warn',
  {
    autoImport: [
      'useI18n',
      't',
      'setLang',
      'getLang',
      'getLangs',
      'getLangLoadState',
      'subscribe',
      'tRef',
    ],
  },
],
```

它只会修复可安全删除的 `virtual:ai-i18n` 导入。改名导入、命名空间导入、类型导入和带注释的导入
不会被自动修改。

## 路径别名与项目配置

项目可以通过共享 settings 显式提供本地源码 alias。显式 alias 拥有最高优先级，适合只在
Vite `resolve.alias` 中配置别名的 JavaScript 项目：

```js
import { fileURLToPath } from 'node:url';

export default [
  {
    settings: {
      'ai-i18n': {
        alias: {
          '@': fileURLToPath(new URL('./src', import.meta.url)),
        },
      },
    },
  },
];
```

第一版支持字符串到字符串的对象形式。replacement 必须使用绝对路径，并指向项目本地源码。
暂不支持 Vite 的数组形式、正则 `find`、`customResolver` 或 resolver plugin。ESLint 不会加载
或执行 `vite.config.*`；需要与 Vite 保持一致时，建议让两份配置导入同一个 alias 对象。

显式 alias 未匹配当前导入时，规则会从正在检查的文件向上寻找最近的 `tsconfig.json` 或
`jsconfig.json`。同一目录同时存在两者时，优先使用 `tsconfig.json`。纯 JavaScript 项目可以
直接使用 `jsconfig.json`：

```json
{
  "compilerOptions": {
    "paths": {
      "@/*": ["./src/*"]
    }
  },
  "include": ["src/**/*.js", "src/**/*.jsx"]
}
```

项目使用非标准配置名、项目引用或特殊工作目录时，可以指定入口：

```js
'ai-i18n/t-static-args': [
  'error',
  { tsconfigPath: './tsconfig.json' },
],
```

`tsconfigPath` 路径以 ESLint 的工作目录为基准，并覆盖自动发现入口。无论使用
`tsconfig.json` 还是 `jsconfig.json`，插件都会解析 `extends`、项目 references 以及
`files`、`include`、`exclude`。该选项沿用现有名称，也可以直接指向 `jsconfig.json`。

Vue SFC 必须被所选项目配置的 `include` 覆盖，例如：

```json
{
  "include": ["src/**/*.ts", "src/**/*.vue"]
}
```

## 候选数量阈值

`static-candidate-limit` 默认在单个表达式超过 1000 个候选时提示。确实存在大型有限文案集合时，
可以提高阈值：

```js
'ai-i18n/static-candidate-limit': [
  'warn',
  { maxStaticCandidates: 2000 },
],
```

这项设置只影响 ESLint 警告，不改变 Vite 的翻译结果。
