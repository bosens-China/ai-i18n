## 选择安装版本

本仓库正在准备首个正式版 `1.0.0`。配置和文档更新不代表 npm 已完成发布。
先查询要安装的包，例如：

```sh
npm view @ai-i18n/vite dist-tags --json
npm view @ai-i18n/vite@1.0.0 version
```

本站正式版安装示例使用 `@^1.0.0`，只接受 1.x 稳定版本，避免安装到历史 `latest` 指向的旧 alpha。
如果 npm 尚无正式版本，示例会报告找不到版本；需要提前试用时，显式把所需包的 `@^1.0.0`
换成 `@alpha`，不要直接删掉版本选择。正式版上架后，默认安装也可使用不带标签的包名。
`@alpha` 只用于主动选择预发布；它不会因为稳定版上线而自动切换到稳定版。

MCP 注册命令同样选择服务包版本；已有项目应先检查已安装版本与锁文件，不要仅更新启动命令。

## 各包独立升级

七个公开包计划以 `1.0.0` 作为首次正式版本，之后分别按自身变化升级。
例如 OpenAI 适配器修复可以只发布 `@ai-i18n/openai@1.0.1`，Vite 包仍保持 `1.0.0`。
版本号不同不等于不兼容，也不需要手动把所有包改为同一个版本。

公开包包括 Vite、Core、Analyzer、ESLint、OpenAI、MCP 和 SQLite。
包之间的内部依赖使用精确版本，由包管理器按各包声明解析；基础包升级时，受影响的消费包也会发布
依赖更新。只安装应用直接使用的包，不为凑齐版本额外安装 Core 或 Analyzer。

## 升级已有项目

1. 查看目标包的 Release Notes，确认修复、功能和不兼容变更；大版本升级先检查迁移要求。
2. 使用项目现有的包管理器更新需要的直接依赖，保留并提交锁文件，不批量强制对齐所有包版本。
3. 运行项目的类型检查、lint、相关测试和完整 Vite Build，验证语言切换、翻译产物及已有 Review/MCP 流程。

Agent 插件和应用 npm 依赖分别更新。更新插件不会自动升级应用依赖；遇到扫描或 MCP 能力缺失时，
应核对各包版本和实际入口，再选择兼容版本升级。
