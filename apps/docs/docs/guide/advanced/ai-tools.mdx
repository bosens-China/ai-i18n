Agent + MCP 是 ai-i18n 提供的两种 AI 翻译方式之一，适合由 AI 编码工具在明确指令下检查、
补齐并验证翻译。如果希望 Vite Dev 或 Build 自动调用模型补译，请改用
[OpenAI Provider](/guide/advanced/ai-translation)。

把 ai-i18n 接到 AI 编码工具时，可以通过三种途径增强 Agent 的能力：

1. **Skills**：安装任务指令集，告诉 Agent 如何按安全流程调用工具补译。
2. **MCP (Model Context Protocol)**：为各类 AI 编码工具提供安全读取和写入翻译文件的底层能力。
3. **文档索引 (llms.txt)**：提供机器友好的官方指南，让 Agent 自己查阅高级配置。

## Skills

你可以在宿主环境（终端或项目库）安装 `@ai-i18n` 提供的标准指令。

在仓库根目录执行：

```sh
npx skills add bosens-China/ai-i18n --skill use-ai-i18n-mcp integrate-ai-i18n -y
```

安装后，Skill 会被保存到 `.agents/skills/` 中。在之后的对话中，你可以直接告诉 Agent：“使用 `use-ai-i18n-mcp` 补译缺失的语言” 或 “使用 `integrate-ai-i18n` 指导项目接入”。

`integrate-ai-i18n` 内置了一张"主题 → 官方文档页面"的索引表：常见配置直接写在 Skill 本地文件里，无需联网；遇到详尽选项表或边界情况时，Agent 会自动抓取下方「文档索引 (llms.txt)」小节所依赖的同一套 Markdown 镜像页面，你不需要手动把链接丢给它。

## MCP

Agent 补译依赖 `@ai-i18n/mcp` 暴露的底层写入能力。你需要在你最喜欢的 AI IDE 或 CLI 工具中注册这个 MCP 服务器。

不同的工具注册方式略有不同：

### Codex

在 `~/.codex/config.toml` 中加入，或者写到项目的 `.codex/config.toml` 中：

```toml
[mcp_servers.ai_i18n]
command = "npx"
args = ["-y", "@ai-i18n/mcp@alpha"]
```

或者在 Codex 桌面端 **Settings → MCP servers → Add server → STDIO** 中填写相同的 `command` 与 `args`。

### Cursor

创建项目级 `.cursor/mcp.json`，或者写到全局的 `~/.cursor/mcp.json`：

```json
{
  "mcpServers": {
    "ai-i18n": {
      "command": "npx",
      "args": ["-y", "@ai-i18n/mcp@alpha"]
    }
  }
}
```

### Claude Code

推荐注册为 local server，避免把绝对路径提交：

```sh
claude mcp add --transport stdio --scope local ai-i18n -- npx -y @ai-i18n/mcp@alpha
```

### Antigravity

创建项目级 `.agents/mcp_config.json`：

```json
{
  "mcpServers": {
    "ai-i18n": {
      "command": "npx",
      "args": ["-y", "@ai-i18n/mcp@alpha"]
    }
  }
}
```

### MCP 能力与边界

接入后，Agent 会获得六个查询、设置与删除工具。注册命令不需要项目路径，MCP 也不会扫描 workspace
猜测项目。Agent 必须先确认目标 Vite 应用，读取其启动脚本和 `vite.config.*`，再把 Vite
`root` 与 `aiI18n({ directory })`（默认 `i18n`）解析成最终绝对
`i18n_directory`。在 monorepo 中，每个 Vite build 分开处理；目标应用不明确时应先询问，
不能把仓库根目录或第一个同名目录直接当作结果。

工具收到目录后会校验绝对路径、目录是否存在，并要求合法的 `translations.json`、
`overrides.json` 与 `extracted/`。缺少协议文件时，请先运行目标应用的 Vite Dev/Build，
不要改为全仓库扫描。

每次调用只返回一份紧凑 JSON 文本，避免同一结果以文本与 `structuredContent` 重复占用
Agent 上下文；结果较大时继续按 `next_cursor` 分页。工具名、字段与错误码使用英文，由
Agent 按当前对话语言解释。

六个工具各自只做一类操作：

- `ai_i18n_list_translations`：首次省略 `source_files` 即可发现文件并直接读取缺失消息；
  也可用 `view: "summary"` 查看文件统计，或用 `view: "all"` 读取全部消息。
- `ai_i18n_set_translations` / `ai_i18n_clear_translations`：设置或清空
  `translations.json` 的具体字段。
- `ai_i18n_list_overrides` / `ai_i18n_set_overrides` /
  `ai_i18n_delete_overrides`：查询、upsert 或删除 `overrides.json` 的人工值。

**安全运作边界：**

1. **分开 AI 与人工结果**：翻译设置/清空只写 `translations.json`；人工设置/删除只写
   `overrides.json`。MCP 不修改 extracted 或 locales。
2. **锁内重读与字段更新**：每批写入都取得跨进程锁并重读最新文件。普通补译默认只填充
   `null`，显式 `overwrite_existing: true` 才允许覆盖。人工设置始终是 upsert；
   `scope: "default"` 影响同一原文的全部调用，`scope: "message"` 只影响带 comment 的
   目标消息。
3. **自动校准与同步**：Vite Dev 运行时会自动重建 locales；否则在下一次
   `vite dev` 或 `vite build` 时完成。
4. **消息不存在时重新读取**：MCP 只报告指定 `message_id` 在该文件中不存在，不推断原因。
   重新调用 `ai_i18n_list_translations` 并原样复制返回的 `source_file` 与
   `message_id`；不要用 `source` 字段代替。

## 文档索引 (llms.txt)

当你希望 Agent 能深入理解本插件的高级用法、配置项甚至特定错误处理，你可以直接在任务对话中丢入本站点的 `llms.txt` 链接：

`https://bosens-china.github.io/ai-i18n/llms.txt`

本官方文档站点基于 Rspress 构建并开启了 SSG-MD 特性，在根路径暴露了对大模型高度友好的纯 Markdown 索引及其全量文本库 (`llms-full.txt`)。
Agent 收到这个地址后，能自动抓取结构化、干净的教程原文并学习。
