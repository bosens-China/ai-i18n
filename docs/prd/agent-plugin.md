# Agent 插件与清单新鲜度

## 当前决策

- Agent 插件携带两份既有 Skill、扫描与辅助脚本，以及 MCP 配置。平台配置只负责声明插件组件。
  Skill 源码统一维护在 `.agents/skills` 中，不复制到应用仓库。应用 npm 依赖与插件分别更新。
- 插件仅支持 Codex；Cursor、Claude Code、Antigravity 继续使用独立 Skill 与 MCP，不构建其他宿主插件。
- `pnpm plugins:build` 只生成 `dist/codex-marketplace/`，市场清单位于
  `.agents/plugins/marketplace.json`，完整插件位于 `plugins/ai-i18n/`。
  `main` 保留源码；CI 将快照发布至 `plugin-marketplace`，用户从该分支安装，无需克隆源码构建。
- Skill 与插件脚本变更会触发市场发布。发布前，先核实插件指定的 MCP 版本已在 npm 发布。
  MCP 在 npm 发布成功后，工作流会更新市场。
  工作流与手动重跑入口见 [发布与 CI](../release.md)。应用依赖不随插件升级。
- 正常结束检查只针对明确的目标应用，缺译或检查失败反馈给当前 Agent 一次，按当前任务授权补译。
  不独立调用模型、覆盖已有译文、确认人工结果或删除历史；不处理中止后的自动继续。
- Codex 仅在 `stop_hook_active: false` 时检查，自动继续后不再阻塞。宿主加载、Hook 信任与启用遵循
  宿主要求，不把结构校验等同于宿主安装实测。

## 扫描复用与 Dev 协调

- Skill、校对和结束检查共用入口扫描及新鲜度判断。没有 Dev 时建立临时 Vite 转换实例；
  存在相同 cacheDir 的活动 Dev 时通过带随机令牌的回环端点请求该进程扫描。
- 当前进程合并扫描请求，独立扫描使用目录旁路锁串行处理。同目录 Build 与历史清理仍需避免并行；
  不支持对活动 Dev 使用不同 mode 或自定义入口，不允许两个 Dev 共用同一应用状态目录。
- 第一版复用整次成功提取结果，不持久化拼接 AST 或模块图。内容摘要覆盖应用或 pnpm workspace、
  配置依赖、环境、相关已安装包版本及有效选项；清单摘要校验保存的提取结果。
- 译文与人工覆盖不进入源码摘要，每次重新读取并计算状态；缺失/改写的清单、源码及候选文件变化
  使缓存失效。缓存位于 Vite cacheDir，可删除重建；内容摘要仍需文件 IO。
- 不确定的自定义转换插件、摘要范围外的消费源码及无法读取的候选路径保守不复用。没有可证明有效的缓存时重新提取，
  不声称覆盖插件自行读取的任意外部输入。扫描期间输入变化和失败不产生可复用记录。
- 缓存摘要与提交保护分开：无关内容更新、声明和工具产物变化不直接拒绝提交；消费源码、配置、
  环境及其余候选文件增删仍受保护。无关坏链接只禁用复用，实际依赖读取失败仍阻止发布清单。
  工具产物忽略规则只影响候选增删保护，不绕过实际消费输入的校验；具体范围以扫描契约为准。
- 扫描助手与结束检查支持显式沿用应用的 Vite 配置加载器，默认保留 Vite 行为，不解析或执行
  package scripts 自动推断加载器，也不因 Monorepo 默认切换 runner。
- 独立扫描助手在扫描 API 完成或报错并排空输出后退出，避免第三方插件遗留监听导致任务超时；
  程序化扫描 API 不结束宿主进程。
- Dev 扫描在临时分析状态中完成，成功后替换活动集合；失败恢复上一份分析状态，避免部分结果
  被当作全量清单。扫描提交保留历史译文与人工覆盖，不运行历史清理或容量淘汰。
- 不生成生产包，不把 Dev 图等同于 Build 专用图；孤立清理前仍需要生产图审查。

## 校对同步

- 当前页面首次打开只使用 Dev 结果；全部页面和独立页按需刷新入口可达清单，包括未访问懒加载页面。
- 可见界面自动刷新；源文案、comment、引用增删、文件重命名和位置变化一起更新。完整扫描移除的
  活动引用不能被首次读取的磁盘快照复活，历史译文仍可保留。
- 刷新失败时保留可辨认的上一份 UI 结果并提示可能过期，修复后自动恢复；轮询不让慢请求一直失效，
  旧响应不能覆盖新请求的结果。保存前复验文案和位置，旧 occurrence 不迁移到新位置。
- 只改译文复用提取结果并同步校对与 Runtime；Dev 原有 Provider 服务继续有效，但扫描本身不追加
  翻译任务。源码提取缓存和 Provider 翻译缓存是两个不同职责。
