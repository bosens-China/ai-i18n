# 独立配置与应用发现

- 一个应用对应一份 ai-i18n.config.ts；公开 aiI18n() 只注册插件，允许显式 configFile，不合并内联选项或父目录配置。共享配置通过 TS import 复用。
- 插件默认在 Vite root 定位配置；文件中的 root 默认配置目录，必须与最终 Vite root 一致。directory、dts 和插件日志路径以配置目录为基准，源码标识仍以 Vite root 为基准。详细参数与迁移见[用户配置文档](../../apps/docs/docs/guide/basic/configuration.md)。
- 配置加载复用 Vite 的独立文件加载能力，支持 TS 与同步/异步配置函数。各入口传递 command/mode；不依赖调用进程 cwd 推断业务路径。不执行 vite.config 即可解析独立配置，但配置及导入模块本身会执行。
- Vite 在配置阶段安装实际插件 hooks；配置及本地导入依赖进入 Dev 重启与扫描缓存失效集合。完整源码扫描仍保留应用 Vite 的别名、框架和虚拟模块环境，不另建扫描器。
- 工作区发现只检查候选文件名，不执行配置；多候选只表示多个应用，不自动选择、继承或合并。跳过隐藏目录、依赖、常见产物目录和符号链接；截断时要求缩小范围，显式路径允许选择未发现的配置。
- MCP 发现与选定配置解析分开。解析只返回路径、语言和本地/远程来源，不返回 Provider、缓存实例或凭证。原有读写工具仍以绝对 i18n_directory 为目标；配置身份及 command/mode 用于写后缓存同步。
- 本地存储保持 translations、overrides、extracted、locales 现有职责和格式，不因配置迁移修改译文。迁移配置目录时必须显式保持现有翻译目录。
- 多应用不共享翻译目录，纯源码 workspace 包属于消费它的应用。无跨进程并发写入保证，配置发现不改变这一边界。
- 内部核心插件测试可直接构造选项；公开接入另覆盖文件加载、构建、扫描、重载和多应用选择。强制独立配置属于不兼容发布。
